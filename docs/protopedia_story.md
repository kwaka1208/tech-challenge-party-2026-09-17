ここからは、このアプリの開発を一緒に進めた私、Kiroが作者からバトンを受け取り、**「あの日の空 あの日、空には 何が見えていた？」**がどのように形になっていったのかをご紹介します。

# ストーリー

## 「その日に空に何があったのか」を見てみたい

このアプリの出発点は、とてもシンプルな問いでした。

> 生年月日と生まれた場所を入力したら、その日の星空を再現できないだろうか。

星空は、誰にとっても同じように見えるものではありません。日付や時刻が違えば天体の位置が変わり、場所が違えば見える方角や高さも変わります。同じ時刻でも、雲、月明かり、街の光、周囲の山によって、見える星の数は大きく変わります。

そこで、単に美しい星空の画像を表示するのではなく、入力された日時と場所を基に、天文学的な計算から星空を組み立てることを目指しました。

## 最初のテーマは「天体の配置」

最初に必要だったのは、その日時、その場所から、どの方向にどの天体があったのかを求めることでした。

恒星にはカタログの赤経・赤緯を使い、地方恒星時と観測地点の緯度から高度・方位角へ変換します。太陽、月、惑星にはAstronomy Engineを使います。さらに、過去や未来の日付でも位置を求められるよう、恒星座標へ歳差補正を加えました。

この段階で、「その日に空に何があったのか」は表示できるようになりました。

しかし、ここで次の疑問が生まれます。

> 天体がそこにあったことと、実際に見えていたことは同じだろうか。

## 「配置」から「見え方」へ

当初は、天文学的な配置を重視する表示と、見栄えを重視する表示を切り替える構想もありました。

開発を進める中で、見栄えのために星を増やしたり、実際より強く光らせたりすると、このアプリが目指す「その日の空を確かめる」という体験から離れてしまうことが見えてきました。

そこで表示を「観測表示」へ一本化し、次の要素をできるだけ一貫したルールで扱うことにしました。

- 星の明るさは等級に応じて表現する
- 太陽高度に応じて昼、薄明、夜を切り替える
- 月明かりによって暗い星の表示を制限する
- 存在しない疑似星を追加しない
- 見栄えだけを目的とした瞬きや強調を行わない

「きれいに見せる」よりも、「なぜこのように見えるのかを説明できる」ことを優先した判断です。

## NASAの星表を使う

初期の星図では、名称付きの主要な恒星を中心に表示していました。

より暗い星まで含めた全天星図へ発展させるため、NASA HEASARCが公開するBright Star Catalog 5th Edition Preliminary（BSC5P）を利用しました。

V等級が3.45より暗く6.5等級以下の8,132レコードを生成時に取得し、名称付き主要恒星と重複しないよう整理してアプリへ同梱しています。

星表を実行時に毎回取得するのではなく、生成済みデータとしてアプリへ含めることで、表示速度と安定性を確保しました。

## 「その夜、見えたかもしれない空」へ

天体配置を正しく計算しても、曇っていれば星は見えません。都市の中心と山間部でも、見える星の数は違います。山や地形の向こう側にある天体は、空に存在していても観測できません。

そこで、星図へ次の3つの観測環境を加えました。

### 過去天候

Open-Meteoの再解析データから、雲量、湿度、降水量、視程を取得します。これらを限界等級や雲の表現へ反映します。

### 光害

NASA GIBSのVIIRS Black Marble夜間光データを使い、放射輝度からBortle階級相当を概算します。都市の明るい空では暗い星を減らし、地平線の光としても表現します。

### 地形

Copernicus DEM GLO-90を使い、観測地点の周囲325地点の標高から方位別の地平線を作ります。山の向こう側に隠れる天体を、恒星と惑星のどちらも同じ基準で除外します。

この3つを加えたことで、アプリは「その日に天体がどこにあったか」だけでなく、「その場所からどのくらい見えそうだったか」を想像できるものへ発展しました。

## 推定を、実測と言わない

過去の環境を扱う上で、特に大切にしたのは、取得した値を実測と断言しないことです。

過去天候は再解析値です。光害は衛星夜間光からの換算です。地形は現在に近い2021年版の数値標高モデルです。建物や樹木、当時の街灯、局所的な雲まで完全に復元することはできません。

そのため、画面ではデータごとに次の情報を表示しています。

- 取得中
- 取得済み
- 推定
- 対象年代外
- 取得失敗
- データ提供元
- 解像度
- フォールバックの有無

取得できなかったデータを、都合よく「晴天」「暗空」として扱うこともしません。その条件だけを計算から外し、ほかの天文計算と表示は継続します。

これは、正確さを装うのではなく、分かっていることと分からないことを分けて伝えるための設計です。

## PCからモバイルへ

通常の星図は、ドラッグで方角を変え、ホイールやボタンで拡大・縮小できます。

さらにモバイルでは、GPSと端末の方位センサーを利用したコンパス追従を追加しました。iPhoneなどでセンサーと位置情報を許可すると、端末の向きに合わせて星図を操作できます。

センサーが利用できない場合や、絶対方位を取得できない場合は、誤った方向を表示するのではなく通常の手動星図へ戻ります。

過去の空を調べる機能と、現在地で端末を動かす体験が、同じ星図の中でつながりました。

## 作者とKiroで進めた開発

このアプリは、作者が目指す体験を少しずつ言葉にし、私Kiroが調査、設計、実装、検証へ落とし込む形で進みました。

最初からすべての仕様が決まっていたわけではありません。

- 時刻を指定できるようにする
- 表示を観測重視へ一本化する
- 表示等級を選べるようにする
- NASAの星表を取り入れる
- 過去天候、光害、地形を加える
- 環境条件を個別にON/OFFできるようにする
- モバイルのコンパスへ対応する
- GitHub Pagesで公開する

実際に動くものを見ながら、必要な機能を追加し、分かりにくいものを整理し、データの出典と制約を明示していきました。

私Kiroはコードを書く役割だけでなく、公式データの調査、ライセンスや精度の確認、API障害時の設計、Canvasのパフォーマンス改善、ドキュメント作成まで担当しました。

一方で、「何を見せたいのか」「どこまでを再現と呼ぶのか」「どの操作を残すのか」という判断は、作者との対話を通して決まっていきました。

## このアプリで体験してほしいこと

このアプリが再現するのは、当日の写真そのものではありません。

再現しているのは、天文学的に計算した天体配置と、公開データから推定した観測環境です。

それでも、日付と場所を入力して星図を開くと、「この方向に月があった」「この星座が昇っていた」「街の明るさや雲で、見え方は違ったかもしれない」と、その日の空を具体的に想像できます。

「あの日の空」を、記録ではなく体験として振り返る。そのための入口として、このアプリを楽しんでいただければと思います。
